How to use aggregate from other environments.

Use of this site signifies agreement with the terms.

Jupyter runs the library itself, in Python on your machine. R, Excel and Google Sheets send a DecL program to an aggregate server and read back exhibits, quantiles and whole distributions. Pick a tab and tick the steps off as you go.

The library itself·Python 3.12 or later, uv fetches it·about five minutes
  1. Windows, in PowerShell
    winget install astral-sh.uv
    macOS or Linux
    curl -LsSf https://astral.sh/uv/install.sh | sh

    Then open a new terminal, so the shell can find uv.

  2. uv init --python 3.13 agg-notebooks
cd agg-notebooks

    aggregate needs Python 3.12 or later. uv downloads 3.13 if you do not have it, and keeps it inside uv, away from any Python you already have.

  3. uv add "aggregate[notebook]"

    One command resolves, locks and installs, so there is no separate uv sync. The notebook extra brings JupyterLab and widgets.

  4. uv run jupyter lab

    A browser tab opens on the folder. File ▸ New ▸ Notebook, Python 3 kernel. Next time, cd agg-notebooks and this one line is all it takes.

  5. Twenty claims a year, gamma mixed Poisson frequency, lognormal severity limited to 2000.

    from aggregate import build, qd
gross = build('agg Gross 20 claims 2000 xs 0 sev lognorm 250 cv 2 mixed gamma 0.4')
qd(gross)
gross.q([0.5, 0.9, 0.99])
    You should see, after the summary table
    array([ 4257.,  8207., 12490.])

  6. Any program in the Loss Lab editor pastes into build() as it stands. Menu ▸ Download models saves every program you built there as one .agg file. gross.plot() draws the density and survival function; gross.density_df is the whole distribution as a DataFrame.

The library's own documentation, with a guided tour of DecL: aggregate.readthedocs.io.

aggregateR, over a server·R 4.1 or later, pure R, no Rtools·about five minutes 
  1. install.packages(c("httr2", "jsonlite", "nanoparquet", "processx"))

    R 4.1 or later. RStudio is the easy way to run these a line at a time.

  2. install.packages("https://github.com/mynl/aggregate-R/archive/refs/heads/master.tar.gz",
                 repos = NULL, type = "source")

    No Rtools needed on Windows: the package has no compiled code. pak::pak("mynl/aggregate-R") also works, but wants Rtools.

  3. To try it, do nothing: the package talks to the public server, https://agg.mynl.com, out of the box.

    For real work, run a private server on your own machine. It needs uv (winget install astral-sh.uv on Windows); the first start downloads the server, which takes a couple of minutes.

    library(aggregateR)
agg_start()     # a private server on 127.0.0.1 for this R session
agg_server()    # which server the session is using
  4. library(aggregateR)
gross <- agg_build("agg Gross 20 claims 2000 xs 0 sev lognorm 250 cv 2 mixed gamma 0.4")
gross
agg_q(gross, c(0.5, 0.9, 0.99))
    You should see
    <agg_handle> agg.Gross #…
  server      https://agg.mynl.com
  grid        log2 16, bs 1
  mean, cv    4672, 0.562
  validation  not unreasonable
 50%   90%   99%
4257  8207 12490
  5. dg <- agg_frame(gross)
dim(dg)          # 65,536 rows, one per bucket
plot(dg$loss, dg$p_total, type = "l", xlim = c(0, 15000),
     xlab = "Loss", ylab = "Probability")
  6. agg_exhibits(gross)              # what it can show
agg_exhibit(gross, "summary")    # a list of data.frames, captions included
agg_library()                    # the example programs, by name and kind
cat(agg_program("Capstone.Gross"))

    A longer first session, gross and net of a treaty with ggplot2, is in the aggregateR README.

Your programs are your data. The public server keeps an audit record of every program it builds. Use made-up numbers there, and agg_start() for anything real.

The AGG functions, over agg.mynl.com·any Microsoft account·about two minutes

  1. Download manifest.xml

    A small XML file that tells Excel where the add-in lives. The upload dialog takes a file, not a link.

  2. Open any workbook at office.com, then Home ▸ Add-ins ▸ More Add-ins ▸ Upload My Add-in, choose manifest.xml, Upload.

  3. =AGG.VERSION()
    You should see
    aggregate_api 1.31.0, aggregate 1.6.0
  4. A1   agg Gross 20 claims 2000 xs 0 sev lognorm 250 cv 2 mixed gamma 0.4
B1   =AGG.BUILD(A1)
B2   =AGG.Q(B1, {0.5, 0.9, 0.99})
    You should see
    B1   agg.Gross#…
B2   4257    8207    12490

    Edit A1 and every cell that depends on it rebuilds. =AGG.EXHIBIT(B1, "summary") spills a whole exhibit.

The upload lives in this browser's storage. Clearing the browser's site data means uploading the manifest again.

The AGG functions, over agg.mynl.com·Microsoft 365 on Windows·about five minutes 
  1. New-Item -ItemType Directory -Force C:\OfficeAddins
Invoke-WebRequest https://agg.mynl.com/excel/manifest.xml -OutFile C:\OfficeAddins\aggregate-manifest.xml

    Or download manifest.xml and move it there by hand.

  2. In Explorer, right-click the folder, Properties ▸ Sharing ▸ Share, add yourself, Share. Note the network path it shows, such as \\YOUR-PC\OfficeAddins.

  3. File ▸ Options ▸ Trust Center ▸ Trust Center Settings ▸ Trusted Add-in Catalogs. Paste the network path as Catalog Url, Add catalog, tick Show in Menu, OK, OK.

  4. Every window, not just the workbook: Excel reads the catalog list at start.

  5. Home ▸ Add-ins ▸ More Add-ins ▸ SHARED FOLDER ▸ Aggregate ▸ Add.

  6. =AGG.VERSION()
A1   agg Gross 20 claims 2000 xs 0 sev lognorm 250 cv 2 mixed gamma 0.4
B1   =AGG.BUILD(A1)
B2   =AGG.Q(B1, {0.5, 0.9, 0.99})
    You should see
    aggregate_api 1.31.0, aggregate 1.6.0
B2   4257    8207    12490

If the Trust Center is locked by your IT department, use Excel on the web instead, or ask a Microsoft 365 admin to deploy the add-in to you (admin center ▸ Settings ▸ Integrated apps). On a Mac, use Excel on the web.

Your programs are your data. The add-in builds on the public server, which keeps an audit record of every program. Use made-up numbers.

The AGG functions, over agg.mynl.com·a Google account, nothing to install·about a minute

  1. Make a copy of the AGG template

    Google asks to Make a copy; say yes. The copy is yours, in your Drive, with a Start here tab and a worked Example tab.

  2. =AGG_VERSION()
    You should see
    AGG for Sheets 1.31.0; aggregate_api 1.31.0, aggregate 1.6.0

    Sheets names them AGG_ where Excel has AGG.: a Sheets function name cannot hold a dot.

  3. A1   agg Gross 20 claims 2000 xs 0 sev lognorm 250 cv 2 mixed gamma 0.4
B1   =AGG_BUILD(A1)
B2   =AGG_Q(B1, {0.5, 0.9, 0.99})
    You should see
    B2   4257    8207    12490

  4. The first time you use AGG ▸ Recalculate AGG cells, Google says it hasn't verified the app. Choose Advanced, then the Go to link, then Allow. It is your own copy of the script asking to show its menu and reach the server. The cells never ask.

  5. =IMPORTDATA(AGG_FRAMEURL(B1, "density_df") & "?cols=loss,p_total,S")

    Sheets asks once, in a bar above the grid, to allow external data. An import holds about 100,000 cells, hence the three columns.

Your programs are your data. Google's servers make the requests, so Sheets always builds on the public server, which keeps an audit record of every program. Use made-up numbers.

A copy keeps the version of the script it was made from. For a newer one, make a fresh copy. The cells compute in the Sheets phone app too.
