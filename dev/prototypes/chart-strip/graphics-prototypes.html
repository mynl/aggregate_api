Widths

The box takes the plot areas' width, which panelLayout already knows: grids[0].left to the right edge of the last panel. Axis furniture is excluded at both ends by the same rule. The left edge is not zero, so the box does not sit under the y-axis labels; the right edge is not the colorbar, which is the value axis of a grid panel and belongs to that panel rather than to the figure. Both edges are then where the panel groups and the panel titles are, so the whole block under the drawing shares one margin.

The relief is the case that needs it. A square panel clamps at SQUARE_MAX, 420, so at a wide host the drawing stops less than half way across and a host width box spans several hundred pixels of white space. box: host width shows that reading.

Which controls go where

The app decided this by where the state is stored, not by what the control changes: a panel control if it went through setPanelView(panel.id, ...), a figure control if it went through the one shared setView(...). The relief is where that showed. It has one panel, so everything in the box was acting on that panel and nothing else, yet only c: gam was drawn as a panel control, because only that one happened to be stored per panel id.

The rule is now what the control changes, which moves five controls up to the panel and leaves the box with what is genuinely figure level.

The move also closes a latent bug. Those five drive the document today, so the first document with two grid panels would have them driving the wrong one. And it leaves Download and reset as the two controls in every figure box on every chart, which is a good test of the rule: they are the only two that are about the drawing rather than about what it shows. unfold relief puts the folded menu back to plain buttons.
