## A. Editor (CodeMirror 6) — `web/src/editor.js`

### A1. Yank (Ctrl-Y) does nothing — Ctrl-K works **[web]**
Root cause: we use the **minimal** `emacsStyleKeymap` from
`@codemirror/commands` (imported line 18, applied via `emacsExtension`, line 47).
That set binds Ctrl-K to `deleteToLineEnd` (a plain delete — *no kill-ring*) and
does **not** bind Ctrl-Y at all. So killed text is never stored and there is
nothing to yank.

Options:
- (a) Replace `emacsStyleKeymap` with a fuller emacs mode that ships a kill-ring
  + yank (e.g. `@replit/codemirror-emacs`). One dependency, gets
  kill/yank/mark-ring and usually fixes A2 as a side effect. **Recommended.**
- (b) Keep `emacsStyleKeymap` and add a tiny custom kill-ring (Ctrl-K stores,
  Ctrl-Y inserts, Ctrl-W/Alt-W/Alt-Y optional). More code, no new dependency.

### A2. Shift-arrow doesn't extend selection; double-click doesn't select word **[web]**
These are CM6 **core** behaviors: `defaultKeymap` (applied line 122-128) carries
the `shift:` selection variants for the arrow keys, and double-click-selects-word
is built into `EditorView`. They *should* already work, so something is
interfering — most likely the emacs keymap sitting above `defaultKeymap`
(line 121) swallowing motion keys, or a selection/focus quirk with
`drawSelection()`. Action: reproduce in isolation; verify keymap precedence and
that no `user-select`/pointer CSS blocks it. Adopting option A1(a) commonly
restores standard selection too — verify together.

### A3. Standardize example programs through `format_program` **[api][up]**
When a program is loaded from the Examples library it should be canonicalized so
the editor always shows tidy DecL. Use
`aggregate.decl_writer.format_program(text, fmt='text')` (NOT
`utilities.format_program` — that path doesn't exist). Note it parses/builds
internally (~Lark cost), so do it **server-side** when serving the example
(in `examples.py` / the examples route), cached, rather than per-keystroke in
the browser. Confirm `format_program` is re-exported on the top-level
`aggregate` namespace; if not, import from `aggregate.decl_writer`.

## C. Bugs

### C1. Building a distortion fails **[api]**
`dist MYD ph .5` builds fine in `build()` but the api rejects it with **HTTP
422** (not 402): `objects.py:343-355` gates on `kind in ('agg','port')` and
raises "api supports 'agg' and 'port' only". To support distortions we need a
distortion code path: classify `Distortion`, cache it, and give it a minimal
pane (parameters + the distortion's own `.plot()`), since it has no
`density_df` / pricing. Decision needed: support standalone `dist` objects now,
or defer and just return a friendlier message? (Note the a4 Price flow below
uses distortions *internally* on agg/port objects, which is independent of
standalone `dist` support.)

### C2. Densities are not shown at all — and sizing **[api][web]**
`density_df` has an endpoint (`objects.py:503`, params `cols/start/stop/
downsample`) but **no tab calls it**, so the SPA never displays a density. There
is also `sev_density_df` (severity on its own grid) with no endpoint yet.

Sizing reality: `density_df` is `2**log2` rows (32k @ log2=15, 262k @ 18) ×
many columns — JSON-ifying the whole thing is the trap. Plan for the **Density**
view (under More, B2):
- Default to `density_df` only (add `sev_density_df` as a second toggle later).
- Filter rows to the support: `p_total > 0` (drop the long zero tails).
- Default a curated column subset (e.g. `loss, p_total, F, S`); let the user
  widen.
- Downsample to a viewable cap (propose ~200-500 rows evenly across the kept
  support) for the on-screen table; the **full** frame stays available via the
  existing `/frame/density_df.csv` download.
- Row/column filter UI: column multiselect + a `p_total >` threshold +
  downsample count. (See D1 — generalize as table filters.)

Decision needed: the on-screen downsample cap (200? 500?) and the default
column set.

## D. a4 enhancements

### D1. Table filters (generalize) **[web][api]**
Per-table row/column selection. First target: the **Stats** table — default to
showing only the `meta` rows plus `mean/cv/skew` measures (the full `stats_df`
is a 25×11 wall). Reuse the same filter primitives for Density (C2). Likely a
small client-side filter over the returned frame plus server-side column
pruning for the big frames.

### D2. `hints{}` should override args + unlock large log2 — **with a guard** **[api][up]**
A DecL `hints{ bs=...; log2=...; }` clause should take precedence over the api's
default `log2=0 / bs=0`. Today `_run_build` (`objects.py:160`) passes the
request's log2/bs straight to `build()`; if the program carries hints, `build()`
may honor them. **Security caveat:** the cap check (`objects.py:238`) only
inspects the *request* log2 — a user could embed `hints{log2=24}` and bypass
`AGGAPI_LOG2_CAP`, a DoS lever. Plan: deliberately allow hints to set knobs, but
post-build (or by inspecting the parsed program) enforce the cap against the
*effective* log2, not just the requested one. Decision needed: cap behavior when
hints exceed it — clamp, or 422?

### D3. Add `bs_window_df` under **More** **[api][web]**
Surface the bandwidth-window diagnostic frame as a More sub-view (alongside
Stats / Density). New endpoint `GET /v1/objects/{id}/bs_window_df` +
a More entry. Confirm the accessor name on the object.

### D4. Price tab — pentagon + distortion analysis **[api][web][up]**
Replace the Price placeholder with a real form and flow. Confirmed upstream
APIs:
- `obj.price_pentagon(*, p|a, <one of P/M/Q/LR/PQ/ROE>)` on **both** Aggregate
  and Portfolio → one-row `total` DataFrame (`PENTAGON_STATS` columns).
- `port.calibrate_distortions(coc, *, p)` — Portfolio only.
- `port.analyze_distortions(*, p)` — Portfolio only → `.pricing_df`.

Inputs: **p** (probability level, required) plus **either CoC** (ROE) **or
LR** (exactly one). Flow:
1. `price_pentagon(p=p, ROE=coc)` or `price_pentagon(p=p, LR=lr)` → display the
   returned one-row pentagon DataFrame.
2. (Portfolio only) `calibrate_distortions(coc=<ROE from pentagon>, p=p)` — note
   `port.calibration_df` should then match the pentagon on overlapping columns.
3. (Portfolio only) `ad = port.analyze_distortions(p=p)` and display:
   - `ad.pricing_df.xs('LR', level='stat')` — format as **percents**
   - `ad.pricing_df.xs('P',  level='stat')` — format `{:,.0f}`
   - `ad.pricing_df.xs('PQ', level='stat')` — format `{:.3f}`
   - `ad.pricing_df.xs('ROE',level='stat')` — format `{:.0%}`

Aggregate objects get step 1 only (the pentagon); steps 2-3 are Portfolio-only.
This is a starting shape — many other cuts of `pricing_df` are possible later.

## E. Matplotlib style — `aggregate.mplstyle` **[up]**

The plot style doesn't match the site: blue (`lightsteelblue`/`aliceblue`)
backgrounds, an oversized serif font, generally off-brand. Goal: align with
`web/src/styles/site.css` — white background, system **sans** UI font, light
`#dee2e6` grid, blue `#0d6efd` primary, a site-harmonized color cycle. The
original is preserved as `aggregate.mplstyle.original` (in git). A restyled
draft is dropped over the existing file for the author to eyeball in Jupyter;
iterate from there. Lives in the `aggregate` repo, not here — so this is an
upstream tweak co-developed against the editable checkout.
